## Risks

- M28 gates the token design. If scaleset v0.5.0 cannot register a repository scale set with a classic or a fine-grained token, the SPEC changes before any code (SPEC Areas of concern 1). The policies endpoint may not answer for every plan or for personal-account repositories, and a read-only token may get 403 or 404 there (SPEC Areas of concern 2); `doctor` then shows `확인 못 함`, not a wrong 통과. `X-OAuth-Scopes` may be missing for classic tokens (SPEC Areas of concern 7), with the same effect.
- Riskiest step: M31. Reason: it routes every REST call of every target through a per-credential wait map shared by target goroutines and holds token values in memory; a mistake either leaks a token into a log line or error, or lets one token's rate limit delay targets of another credential (or miss targets of the same one). Mitigations: the map key is a SHA-256 digest, not the token; `config.Credentials` prints `<redacted>`; tokens are registered in `logging.Secrets` before any client exists; `-race` tests run two targets on one token and two on different credentials.
- Token values in output. Every new command could print a token through an error that quotes a file's content or a URL with a credential. Mitigations: R276 and R314 checks run before any check that quotes a value; token file errors never contain path or content; `doctor` passes each line through the registered secrets; the backstop `redactKnownFormats` in `internal/logging` already hides the six prefixes in logs; every command's tests assert that a fixture token appears in neither stdout nor stderr (R277).
- Test fixtures that look like tokens. A literal token-shaped string in a committed test could trip GitHub's secret scanning push protection on this public repository and the document checker. Mitigation: tests build fixture tokens at run time from a prefix and generated characters; no token-shaped literal is committed.
- Stopping the service for the real runs (M41 steps 3–9). A second scaler beside the service is not an option (lock R78, clean-up R16; Decisions). The user has disabled the deploy workflows of the service's repositories, so no job waits on the service meanwhile. Rebuilding the runner image moves the `actions-runner-scaler-runner:local` tag; the service keeps working only while its old image ID stays local, so no image prune runs (SPEC Areas of concern 10). The service's binary is replaced only in step 9. R308's job runs on a test branch of Q that is deleted afterwards; Q's default branch is not touched.
- R308 timing: launchd's `ThrottleInterval` 60 can hold a start for up to 60 s after the previous start (seen in 0002 M26-9); the previous start is before step 3, so step 9 is expected to start at once; if not, the 60 s count is recorded from the actual start and reported.
- Byte-level edits (M36) handle only files whose targets are `[[targets]]` header blocks; anything else is refused with a paste block, and the re-decode comparison refuses rare shapes such as a multi-line string holding a line that starts with `[` (SPEC Areas of concern 9). An editor holding the file does not take the lock (SPEC Areas of concern 11).
- Per-token waits treat two tokens of one person as separate, so both may get one rate-limit answer each (SPEC Areas of concern 4). Organization policies (classic tokens blocked, fine-grained approval pending) show as R279 failures with the header hints when present (SPEC Areas of concern 5). A classic token's `repo` scope reaches every repository of its person (SPEC Areas of concern 3); README orders the credentials (R307). Tokens expire (SPEC Areas of concern 6); `doctor` warns 7 days ahead and the scaler shows the 401 as that target's error. A private App installs only on its owner (SPEC Areas of concern 8); `app-link` and README say so.
- `init` and `add-repo` call `config.Load`, which reads the key and token files: a FIFO at such a path does not block (`openRegular` with `O_NONBLOCK`, as today), and no file content enters an error.

## Decisions

- Code rules follow AGENTS.md and the 0001 and 0002 PLAN Decisions this plan does not change: constructor injection, small interfaces in the consuming package, no global state, short comments that give reasons.
- The token check (M28) runs before any code, as a throwaway program outside the repository, as 0002 M19 did. Method not chosen: an `integration` test in this repository (it needs the code first, which is wasted if the check fails).
- `add-repo` and `remove-repo` edit bytes and verify by decoding the result. Method not chosen: decode and re-encode with `BurntSushi/toml` (its encoder writes no comments and its own key order, so a hand-edited file would lose both; inferred from the encoder writing values from Go data only, unverified against its source).
- The config file lock is `flock` on a separate `<file>.lock` that is never removed. Methods not chosen: `O_EXCL` lock files as git's `.lock` and client-go use (a crashed process leaves the file and blocks the next command until removed by hand; `flock` is released by the kernel when the process ends); `flock` on the config file itself (the rename gives the path a new inode, so the next command would lock a different file); removing the lock file after use (contenders could lock two inodes, as runscaler's `internal/lock/lock.go` comment says).
- `init` writes a temporary file and links it into place. Method not chosen: `O_CREATE|O_EXCL` on the target path (a failure while writing leaves a partial file at the path, which R282 forbids).
- The runner image is marked with the OCI pre-defined keys `org.opencontainers.image.source` and `org.opencontainers.image.title`, from the image-spec module's constants. Method not chosen: a custom label (no meaning outside this project, and it would not correct the base image's inherited `source` value).
- Terminal detection uses `golang.org/x/sys/unix.IoctlGetTermios`. Method not chosen: adding `golang.org/x/term` (a new module for one call; `x/sys` is already required).
- R280's map key is the SHA-256 of the token value. It groups exactly as "per token value" does. Method not chosen: the raw token as map key (a printed key or a debug dump would show it).
- A token target's check is a `targetAuth` implementation beside the App's, chosen per target when the daemon builds it. Methods not chosen: a credential kind switch inside `targetRun.start` (every later credential kind would edit the start phase); one REST client per token shared by its targets (R280 asks only for shared waits; separate clients keep 0002's per-target client model).
- R274's list shows a credential-bearing URL as `targets[<i>]`. Reason: R314 forbids printing that value anywhere; this is the only R274 case where the SPEC's "show every `targets.url`" cannot hold.
- `doctor` lives in its own package with its own small interfaces and calls the `github` and `docker` clients once each. Method not chosen: reusing the daemon's start path (it retries, takes the lock and creates registration tokens, all forbidden by R299 and R302).
- The real runs stop the service for steps 3–9 instead of running a second scaler beside it. Methods not chosen: a second scaler with the same `HOME` (the lock R78 stops it); with another `HOME` (its R16 clean-up removes the service's runner containers and fails their jobs).
- Tests build token-shaped fixtures at run time. Method not chosen: literal fixtures (GitHub push protection on the public repository and the document checker reject token-shaped literals).
