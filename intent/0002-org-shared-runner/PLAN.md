This plan covers the revised SPEC (5d80a5a), in which every target is one repository (owned by an organization or a personal account) with its own scale set. The first version of this change registered one scale set per organization; it was planned in M0–M18 (this file at 1cae3d2 and its later edits up to 5d80a5a), implemented and tested up to bae1c63. That work is recorded below under "First version" and stays in the code except where M20–M25 change it. The work of this revision is M19–M27. In code comments, cite this plan as `0002 PLAN M<n>` and this SPEC as `0002 SPEC`. "Target key" means the lower-case `<owner>/<repo>` of a target (`github.Target.Key`); "config order" means the order of `[[targets]]` in the file.

## Risks

- M19 gates the design. If two repositories of one owner cannot each hold a scale set named `linux-arm64-deploy` in group 1, or a personal-account repository refuses group 1, the registration design changes (SPEC Areas of concern 19, 7); M20 does not start until the SPEC and this plan are revised with the user's approval.
- Riskiest step: M21. Reason: it adds state shared by target goroutines (the installation map) and a pointer that a target error wait retry rebinds; a mistake either lets one installation's REST rate limit miss other targets of that installation (more 429 answers) or lets it delay targets of another owner. Mitigations: the map is behind one mutex and never shrinks; the rebind is one atomic store after a successful lookup; tests run two targets' lookups under `-race`, and a retry test checks the rebind.
- M20 changes the type every package uses; a missed fixture or call site fails to compile, which the checks catch. The real risk is a rule mismatch between `config` and `github.ParseTargetURL` (one accepts a URL the other rejects, so the scaler passes validation and then fails at start); `TestTargetURLRuleMatchesGitHub` runs both rules on the same table.
- `targets.max-runners` defaults to 1 now; a first-version config without the key silently halves that target's capacity. The R232 text and the README migration notes say so (SPEC Design 설정 파일).
- A job in repository A with `runs-on: linux-arm64-deploy` reaches only A's scale set (repository-level registration, R240). If an organization-level runner or scale set with the same label exists, GitHub may route jobs to it, and a lookup that returns two scale sets is a permanent error for that target (SPEC Areas of concern 16). M26-1 checks runner lists per repository.
- Runner names are `<label>-` and 8 hex digits for every repository; if names collide across repositories of one owner, JIT issue fails with `RunnerExistsError` and counts as a start failure (R64), retried with a new name (SPEC Areas of concern 8).
- The installation lookup of a repository outside the installation may not answer 404 (SPEC Areas of concern 5); then the R237 text does not appear and the target's last error shows the other status. M26-12 records it.

## Decisions

- Code rules follow AGENTS.md and the 0001 PLAN Decisions that this plan does not change.
- The real check (M19) runs before any code change, as a throwaway program outside the repository. Method not chosen: an `integration` test in this repository (it would need the code change first, and the change is wasted if the check fails); calling `internal` packages from a scratch module (Go's internal-package rule forbids it).
- `github.Target` holds only owner and repository; the organization kind is removed, not kept beside it. Method not chosen: a kind enum with one value (dead branches in every caller).
- The configuration keeps its own URL rule, kept in step with `github.ParseTargetURL` by a test, as in the first version. Method not chosen: `config` importing `github` (a new dependency from the configuration package to the network package).
- The R232 and R234 texts follow the existing key prefix of configuration errors, so the shown lines are `targets[<i>].url: "<value>" names an organization or account; ...` and `targets[<i>].runner-group: no longer used; ...`. Method not chosen: printing the SPEC text without the index (the user could not tell which entry is wrong).
- R266's routing is a `scaler.RateLimits` implementation in the daemon that sends the two REST ops to the installation's `NextAllowed` and every other op to the target's. Methods not chosen: installation-qualified kinds inside `retry.NextAllowed` (changes every `Op` user); one `NextAllowed` per installation for all ops (would join the Actions service waits of one owner's targets, against R265).
- Each target keeps its own REST client and installation token cache. Method not chosen: one REST client per installation (saves token requests but adds shared token state and rebinding; R266 asks only for a shared wait).
- delete-scaleset answers any argument that is not a configured repository, an unparsable one and an organization URL included, with the R269 not-in-config text, before any GitHub call. Method not chosen: a separate URL-format error (R269 lists an organization URL under "not in the config").
- R247 is proven by a new placement test on the unchanged code. Method not chosen: changing `placement.entry` without a failing test.
- First-version decisions that stay: the verdict is made and recorded inside the `POST /v1/event` handler; `Decide` lives in `gate` and reads IDs from raw JSON bytes; a body read error aborts the handler with `panic(http.ErrAbortHandler)`; R131's 1 s bound is tested on the real clock without `-race`; one runner table per server with both limits checked in `Table.Add`; one server-wide `Placer.mu` with the lock order `scaleMu` → `Placer.mu` → `Table.mu`; R226 uses the deficit as computed at each message; R242 looks each unjudged runner up by name; the hook sends the event file content and switches to `GET /v1/verdict` after any answer other than 401, a connection failure or a final verdict. Their reasons and rejected methods are in this file at 5d80a5a.
- Test workflows and test configurations stay outside this repository (they name test repositories). Method not chosen: committing them (they are not part of the product).
